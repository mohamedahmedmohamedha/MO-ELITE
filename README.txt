أهم ما تم إصلاحه/تطويره:
1) مزامنة بيانات الحساب عبر Firestore مع استمرار العمل محليًا عند انقطاع الإنترنت، والحساب/الإيميل هو المصدر الأساسي للبيانات بين الأجهزة.
2) كل بيانات الطالب الأساسية ومقاييس المستوى والاختبارات والأخطاء وجلسات التركيز وخطة اليوم والقياس التاريخي داخل state المتزامن.
3) جلسة المؤقت المؤقتة draftFocus يتم حفظها محليًا، وتُرفع للسحابة دوريًا أثناء التشغيل حتى يمكن استعادتها بعد فتح الحساب من جهاز آخر.
4) منع مزامنة بيانات الدخول من إعادة تنشيط حساب موقوف بالخطأ.
5) اختصارات كمبيوتر للمؤقت:
   - Space = تشغيل/إيقاف مؤقت
   - P = إيقاف/استكمال
   - F = إنهاء وتسجيل
   - R = مسح المؤقت
   - Ctrl/Cmd + S = حفظ ومزامنة
   - Ctrl/Cmd + K أو / = فتح البحث السريع
6) لوحة الأدمن تقرأ الملف المتزامن للطالب وتعرض معلومات أوسع: الصف/المسار، الهدف اليومي، إنجاز الخطة، تركيز اليوم، آخر اختبار، آخر قياس مستوى، المواد، وبيانات الذكاء.
7) حسابات Firebase Authentication تبقى المصدر الآمن للهوية وكلمة المرور؛ لا يتم حفظ كلمات المرور داخل الملفات.

النشر:
1) ثبّت Firebase CLI وسجّل الدخول.
2) تأكد أن المشروع الحالي هو mo-elite.
3) داخل functions نفّذ npm install.
4) من جذر المشروع نفّذ:
   firebase deploy --only functions,firestore:rules,hosting

ملاحظة مهمة:
لو تم فتح التطبيق بحساب قائم، البيانات تنتقل بين الأجهزة فقط بعد تسجيل الدخول بنفس الحساب واتصال الإنترنت. لا تُشارك كلمة مرور الحساب أو ملف firebase-config خارج مشروعك العام إلا مع علمك أنه يحتوي على معرفات Firebase العامة اللازمة للتطبيق.

8) عند أول دخول لحساب بلا بيانات سحابية يظهر اختيار بدء من نسخة JSON أو بيانات الجهاز أو حساب فارغ. بعد إتمام البداية لا يتكرر السؤال لهذا الحساب.
9) المزامنة الحية تستخدم Firestore realtime listener مع دمج محافظ للبيانات ذات المعرفات حتى لا تضيع إضافات جهاز من جهاز آخر عند العمل المتوازي.
10) زر التصدير الاحتياطي لم يعد ظاهرًا في الواجهة الرئيسية لتقليل الاعتماد على الملفات؛ الاسترجاع بالملف متاح من شاشة البداية كخيار طوارئ.


11) طبقة حفظ Firestore الدائمة مفعلة للويب مع مزامنة متعددة التبويبات عندما يدعمها المتصفح، مع استمرار localStorage كخط أمان محلي. Firestore نفسه يدير طابور الكتابات عند العمل دون اتصال ثم يزامنها عند عودة الشبكة.
12) طبقة sync metadata تتعقب IDs الأساسية للحالة لتجنب إعادة إحياء العناصر التي حُذفت على جهاز آخر أثناء الدمج المتوازي.
13) محرك المستوى المحسن يدمج نتائج الأسئلة ودرجات الاختبارات المسجلة، ويعطي درجات الاختبارات الخارجية وزنًا مستقلًا مع حداثة الدليل، كما يستخدم التقدير التشخيصي كـ prior ضعيف فقط عند صغر العينة.
14) مؤشر الجاهزية أصبح مرتبطًا فعليًا بجودة القياس + التغطية + الثبات + تنفيذ الخطة + انتظام التركيز + عبء الأخطاء.
15) مركز الذكاء يحتوي على «صحة المنظومة» لمتابعة الاتصال والحساب وFirestore وجودة البيانات وحجم الحالة.
16) Service Worker يحمل رقم إصدار جديد لإجبار المتصفح على التقاط نسخة الواجهة المحدثة بعد النشر.
